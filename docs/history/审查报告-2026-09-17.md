# 项目审查报告 · campus-login

- 审查对象：`campus-login/`（CLI `campus_login.py` + GUI `campus_gui.py` + 托盘 `tray_icon.py` + `build.bat` / `CampusNet.spec` 打包链 + `reference/` 逆向材料）
- 审查日期：2026-09-17
- 审查方式：全量静态阅读 + 离线逻辑自检（12 项）+ 实网只读验证（`test` 子命令）+ 边界探针（配置容错 / 编码 / 并发）

## 一、总体评价

工程质量在同类个人工具中属于较高水平，三点值得肯定：

1. **协议逆向有据可查且经实测闭环**。`callback` 必须置于查询参数首位、`R3` 服务类型真实映射（0 校园网 / 1 移动 / 2 电信 / 3 联通 / 4 广电）、`msg` 数字码表、`user_account=",0,"+账号` 前缀等关键结论均有抓包或页面 JS 佐证，README 与代码注释一致。
2. **架构克制**。协议层与界面层分离（`LOG_HOOK` 注入日志回调，核心模块不依赖 tkinter），全程仅标准库；托盘用纯 ctypes 实现 `Shell_NotifyIconW`，打包后无第三方依赖负担。
3. **上一轮（2026-09-07）问题已全部落实**。见第四节复核结果。

主要问题集中在**凭据治理**与**配置一致性**两类，而非协议或算法。

## 二、本轮新发现问题

### P1-1 发布目录内残留带真实凭据的配置文件

- 位置：`campus-login/dist/campus_login.json`
- 现状：包含真实学号与**明文密码**，且 `auto_login_on_start=1`、`auto_watch=1`。
- 影响：
  1. 与 README「发布给同学时把 `dist\CampusNet.exe` 单独复制即可，**无需附带** `campus_login.json`」的说明冲突——按目录整体打包分发即泄露凭据；
  2. 该配置会让接收方启动后**静默自动登录并常驻托盘**，实际使用作者账号，且提示信息不明显。
- 建议：发布前删除该文件；同时在 README「发布」小节加一条前置检查项。
- 处置需用户确认（涉及删除本机文件）。

### P2-1 配置双份且已分叉，CLI 与 exe 各读一份

- 位置：`campus_login.py:38-43`（`APP_DIR` 取值规则）
- 事实：脚本模式 `APP_DIR = __file__ 所在目录`，exe 模式 `APP_DIR = sys.executable 所在目录`。实测两份配置的键集合已不同：

| 配置路径 | 消费方 | 独有键 |
|---|---|---|
| `campus-login/campus_login.json` | `python campus_login.py` / `python campus_gui.py` | — |
| `campus-login/dist/campus_login.json` | `dist\CampusNet.exe`（含 `启动校园网登录.bat`） | `auto_login_on_start`、`auto_watch` |

- 影响：用户改一处（如换密码、切 ISP），另一处不生效；且两处错误表现不同（一个报密码错误，一个"看起来正常"）。当前凭据恰好一致，但这只是巧合。
- 建议：README 增加显式说明；或将 exe 模式配置路径也固定到源码目录（牺牲可移植性），或反向——分发时以 `dist` 为唯一配置源。

### P2-2 首次交互式配置的默认 ISP 与项目默认值相矛盾

- 位置：`campus_login.py:616` `isp = input("请选择 [0]: ").strip() or "0"`
- 矛盾点：
  - `DEFAULT_CONFIG["isp"] = "1"`（中国移动，与真实抓包一致，README 亦如此声明）
  - `campus_gui.py:775` 兜底为 `self.cmb_isp.current(1)`（中国移动）
  - 唯独 CLI 首次交互默认落到 `0`（校园网）
- 影响：首次在命令行初始化、一路回车的用户会写入错误的 `R3`，表现为 `msg=0/1`（账号或密码不对），而真实原因是运营商选择错误，排查线索不足。
- 建议：提示与默认值统一为 `1`（或按 `DEFAULT_CONFIG["isp"]` 动态生成提示文本）。

### P2-3 抓包文件含明文密码（沿用上一轮结论，仍未处置）

- 位置：工作区根目录 `新建 文本文档.txt`
- 影响：一条完整 `curl` 命令，含明文 `upass` 与 `user_password`。该文件在项目根、且非源码目录，易随目录整体分享。
- 建议：删除，或将密码替换为占位符后移入 `reference/`。

### P3-1 `load_config` 异常捕获不完整，畸形配置导致崩溃

- 位置：`campus_login.py:125-133`（`except (ValueError, OSError)`）
- 实测（5 个畸形样本）：

| 配置内容 | 结果 |
|---|---|
| 截断 JSON `{"server": "1.1.1.1"` | 正常回退默认 ✅ |
| `5` | **未捕获 `TypeError: 'int' object is not iterable`** ❌ |
| `[1, 2]` | **未捕获 `TypeError: cannot convert dictionary update sequence`** ❌ |
| `"hello"` | 正常回退默认 ✅ |
| `null` | **未捕获 `TypeError: 'NoneType' object is not iterable`** ❌ |
- 建议：`except Exception` 或改为 `data = json.load(f); if isinstance(data, dict): cfg.update(data)`。

### P3-2 `save_config` 非原子写

- 位置：`campus_login.py:136-138`
- 事实：直接 `open(CONFIG_PATH, "w")` 截断写入（探针确认无 tmp+replace）。
- 影响：写盘期间进程被杀 / 断电 → 配置截断。虽有回退默认逻辑兜底，但**账号密码会一并丢失**，且用户已在线时不易察觉。
- 建议：写临时文件后 `os.replace()`。

### P3-3 自动登录与守护共用同一停止事件

- 位置：`campus_gui.py:688`（`_task_auto_login` 检查 `self.watch_stop.is_set()`）与 `712-722`（`_watch_toggle`）
- 影响：自动登录最多重试 6 轮 × 10 秒 ≈ 60 秒窗口内，用户点「停止守护」会顺带中断自动登录重试。
- 建议：新增独立 `self.auto_login_stop` 事件。

### P3-4 `refresh_status` 无在途去重

- 位置：`campus_gui.py:628-629`
- 事实：方法体仅 `threading.Thread(target=self._task_refresh, daemon=True).start()`，无 `busy` 或在途标志；调用方有 60 秒周期刷新、托盘恢复、操作完成 `dirty` 三处。
- 影响：网络慢时（`check_status` 5s + `check_internet` 最长 10s）可叠加并发线程，结果乱序覆盖状态卡。单次代价小，长期驻留不理想。
- 建议：加 `self._refreshing` 标志或复用 `busy`。

### P3-5 守护模式不热重载配置

- 位置：`campus_login.py:554-562`（`cmd_watch`）、`campus_gui.py:728-729`（`_task_watch`）
- 事实：两者均在循环外读取一次 `cfg` 并固定 `interval`。
- 影响：守护运行中修改服务器地址 / 端口 / 间隔不生效，需停止再启动。对常驻托盘的使用方式（改设置是常见动作）体验有影响。
- 建议：循环内重读 `load_config()`。

### P3-6 重定向输出被强制为 UTF-8

- 位置：`campus_login.py:660-665`
- 隔离验证（显式置 `PYTHONUTF8=0`、清除 `PYTHONIOENCODING`）：

```
重定向后裸 stdout.encoding = gbk
模拟 main() 的 reconfigure 之后 = utf-8
```

- 影响：`python campus_login.py status > log.txt` 后，在代码页 936 的 cmd 中用 `type` / `findstr` 查看中文乱码。
- 边界说明：**交互式控制台不受影响**——Python 3.6+ 在真实控制台下默认即为 UTF-8（`WriteConsoleW`），四个 `.bat` 的 `chcp 65001` 亦已覆盖双击路径。仅影响"重定向 + 传统 cmd 消费者"这一窄场景，可视为可接受取舍。
- 建议（可选）：改为 `sys.stdout.reconfigure(errors="replace")`，保留控制台自身编码，只保证不抛 `UnicodeEncodeError`。

### P3-7 仓库卫生

- 无 `.gitignore`、无版本控制（`Test-Path .git` = False）。
- `build/CampusNet/`（`base_library.zip`、`PYZ-00.pyz`、`localpycs/*.pyc` 等 PyInstaller 中间产物）与 `__pycache__/`（3 个 `.pyc`）留在项目内，均属可从源码重建的派生物。
- 建议：补 `.gitignore`（`build/`、`dist/`、`__pycache__/`、`*.json` 中除模板外的凭据文件）。

### 提示级

- GUI 缺少「测试连通性」入口，CLI 有 `test` 子命令，功能不对称。
- `campus_gui.py:_restore_from_tray` 中 `self.root.deiconify()` / `lift()` 未包 `try/except tk.TclError`；`_real_quit` 已 `destroy()` 后若队列中仍有 `("watch", False)` 消息被 `_poll` 取到，会触发未捕获异常。概率低、后果轻（回调内异常）。
- `campus_gui.py:780` 附近 `_load_settings_ui` 在 `for...else` 中兜底 `current(1)`，逻辑正确，但与 P2-2 的默认值问题同源。

## 三、固有风险（非代码缺陷，不做修复建议）

- **认证全程明文 HTTP**：`upass` 与 `user_password` 均为明文上送，`en_md5=0`。同一二层网段内可被嗅探。这是 Dr.COM 传统 ePortal 协议本身的设计，代码层面无法缓解。
- **配置文件明文存储密码**：若需加固，`ctypes` 调 `crypt32.CryptProtectData`（DPAPI）可在不引入第三方依赖的前提下做到仅当前用户可解密。属增强项，非缺陷。

## 六、建议处置顺序

1. **立即**：清理 `dist/campus_login.json` 与根目录抓包 `txt`（P1-1、P2-3）——凭据泄露风险最高、成本最低。
2. **短期**：P2-2 默认 ISP 统一为一处常量；P3-1 放宽异常捕获（两处各改 1 行，收益/成本比最高）。
3. **中期**：P2-1 配置路径说明、P3-3/P3-4/P3-5 并发与热重载、P3-2 原子写。
4. **长期（可选）**：DPAPI 加密密码、补 `.gitignore` 与版本控制。
